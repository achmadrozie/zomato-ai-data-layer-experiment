# Does better data modelling improve AI analytics?

> A controlled experiment: give an LLM progressively richer data layers (source → staging → intermediate → core → marts → metrics → glossary) and measure how answer correctness changes.

Companion repo for the Medium article [*Does better data modelling actually improve AI analytics?*](https://medium.com/@achmad.rozie/does-better-data-modelling-actually-improve-ai-analytics-7e3894d1e244). Builds on [`zomato-ai-analytics-pipeline`](https://github.com/achmadrozie/zomato-ai-analytics-pipeline).

[![Progressive data access and data system design](assets/diagram_data_system.png)](assets/diagram_data_system.png)

## Problem

Teams invest in staging, core models and semantic layers, but it is rarely measured whether an AI analyst answers better because of them. This repo tests that: same questions, same models, only the data access changes.

## Headline result

Mean correct answers out of 25 (3 repetitions each):

| Model | A: source/staging | F: all layers + glossary |
|---|---|---|
| GPT-4.1 | 11.3 | 18.3 |
| GPT-6 Luna (high reasoning) | 19.3 | 25.0 |

[![Correct answers by model and by arm](assets/fig1_correctness.png)](assets/fig1_correctness.png)

- Most of the gain comes from the intermediate and core layers, plus the glossary. Marts and metrics add no detectable gain over core.
- The glossary is what makes the three policy questions (Q22–Q24) answerable, by construction: arms A–E score 0 there.
- Cost is not monotonic. Richer context raises cost per correct answer by ~1.2× for both models by arm F, except GPT-4.1 on core, where it is cheaper (0.83×).

## Experiment design

[![Experiment setup](assets/table1_experiment_setup.png)](assets/table1_experiment_setup.png)

- 25 business questions, 6 access arms (A–F), 2 models, 3 repetitions = 900 attempts. `gpt-4.1` runs at temperature 0, `gpt-6-luna` at high reasoning effort; job order is shuffled with seed `20261021`.
- The model never sees reference answers.
- Grading is deterministic ([`scripts/autograde.py`](scripts/autograde.py)) against [reference answers](experiments/answers_25.md).
- Details: [`experiments/experiment_design.md`](experiments/experiment_design.md). Scoring and reproduction: [`experiments/README.md`](experiments/README.md).

### How an attempt runs

1. The runner gives the model its arm's catalog (plus metric definitions in E and F, and the glossary in F) and one question.
2. The model chooses an action: `sql`, `metricflow` (E/F only), `answer` or `clarify`.
3. The runner validates SQL and executes it. Errors are returned to the model.
4. The model has up to 3 queries to answer or request a missing rule.
5. Every action, result, answer, token count and timing is stored; `autograde.py` scores the final answer against the frozen reference.

## Getting started

```bash
export DBT_SNOWFLAKE_ACCOUNT=... DBT_SNOWFLAKE_USER=... DBT_ENV_SECRET_SNOWFLAKE_PASSWORD=...
cp dbt_zomato/profiles.yml.example .local/dbt/profiles.yml
# run snowflake/project1/01_initialize.sql once, then:
dbt build --profiles-dir .local/dbt --project-dir dbt_zomato
```

The profile and run guard require `ZOMATO_DLR`, so this project cannot write to the Project 0 `ZOMATO` database. `01_initialize.sql` copies `USERS` without `PASSWORD` and preserves the first snapshot on re-run.

## Tech stack

| Stage | Tools | Role in the experiment |
|---|---|---|
| Storage and warehouse | AWS S3 (IAM role), Snowflake | Source tables cloned into `ZOMATO_DLR`; `USERS` copied without `PASSWORD` |
| Transformation | dbt Core (dbt-snowflake) | Staging, intermediate, core and mart models, each with docs and tests |
| Semantic layer | MetricFlow | 6 semantic models, 19 metrics |
| Context layer | Versioned Markdown glossary (`context/v1`) | Business rules CTX-01–03 given to arm F only |
| Evaluated models | OpenAI GPT-4.1, GPT-6 Luna | Answer 25 questions using only their arm's catalog |
| Safety | Runner-side validation (`sqlglot`): single SELECT, table allowlist, blocked sensitive columns, row limit | Models have no credentials or filesystem tools; the warehouse connection still uses the dbt role, not a dedicated read-only identity |
| Evaluation | Python scripts (`run_experiment`, `autograde`, `build_results`) | 900 attempts, deterministic grading, generated `RESULTS.md` |

## Limits

- One dataset, one domain, two models, 3 repetitions: directional evidence, not a general claim.
- Glossary policy rules are written for this snapshot, not real Zomato policy.
- Cost figures are estimates from token usage.
